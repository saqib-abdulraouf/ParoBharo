Class-Based Views (CBVs)

Convert Function-Based Views to Class-Based Views — cleaner, shorter, job-ready!
{% verbatim %}
🎉 Zabardast! Aap ne apna pehla poora CRUD app bana liya hai — Create, Read, Update, Delete sab function kar rahe hain! Ye bohat bari achievement hai, khaaskar 4 mahine ke break ke baad.

Ab Week 3 ka aakhri part karte hain: Class-Based Views (CBVs) — jobs mein ye bohat pucha jata hai, kyunke professional Django projects mostly CBVs use karte hain (kam code, zyada organized).

FBV vs CBV — Farq Samjhein

📝
Function-Based Views
Jo humne abhi banaya — functions se
More code, manual control
def task_list(request):
➜
📦
Class-Based Views
Ab classes se karenge
Less code, more organized
class TaskListView(ListView):
Key Insight: Ab wahi kaam hum classes se karenge — Django khud bohat sa boilerplate code handle kar leta hai.

1 Views.py Mein CBVs Add Karein

tasks/views.py ke upar ye imports add karein:

tasks/views.py — Imports 
from django.views.generic import ListView, CreateView, UpdateView, DeleteView
from django.urls import reverse_lazy

Phir neeche CBVs likhein:

tasks/views.py — CBVs 
class TaskListView(ListView):
    model = Task
    template_name = 'tasks/task_list.html'
    context_object_name = 'tasks'


class TaskCreateView(CreateView):
    model = Task
    form_class = TaskForm
    template_name = 'tasks/task_form.html'
    success_url = reverse_lazy('task_list')


class TaskUpdateView(UpdateView):
    model = Task
    form_class = TaskForm
    template_name = 'tasks/task_form.html'
    success_url = reverse_lazy('task_list')


class TaskDeleteView(DeleteView):
    model = Task
    template_name = 'tasks/task_confirm_delete.html'
    success_url = reverse_lazy('task_list')
Ye kamaal ki baat samjhein: Sirf 4-5 lines mein humne wahi kaam kar diya jo pehle 15-20 lines ke function mein likha tha!

Django khud handle karta hai:
✅ GET request pe form/list dikhana
✅ POST request pe validate aur save karna
✅ Object dhundna (get_object_or_404 ki zaroorat nahi)

Har class samjhein:

model = Task Django khud samajh jata hai konsa data chahiye
context_object_name = 'tasks' Template mein variable ka naam (warna default object_list hota)
form_class = TaskForm Konsa form use karna hai (Create aur Update ke liye)
success_url = reverse_lazy('task_list') Save/delete ke baad kahan redirect karna hai
reverse_lazy (na ke reverse) Class ke andar use karte hain, kyunke class load hote waqt URLs abhi ready nahi hoti

2 URLs Ko CBV Se Connect Karein

tasks/urls.py ko update karein (FBVs ko CBVs se replace karte hain):

tasks/urls.py 
from django.urls import path
from . import views

urlpatterns = [
    path('', views.TaskListView.as_view(), name='task_list'),
    path('create/', views.TaskCreateView.as_view(), name='task_create'),
    path('<int:pk>/update/', views.TaskUpdateView.as_view(), name='task_update'),
    path('<int:pk>/delete/', views.TaskDeleteView.as_view(), name='task_delete'),
]
.as_view() Zaroori hai! Ye class ko ek function jaisa banata hai jo Django URLs samajh sakein

📊 FBV vs CBV — Side by Side Comparison

Function-Based View (FBV)

def task_list(request):
    tasks = Task.objects.all()
    return render(request, 
        'tasks/task_list.html', 
        {'tasks': tasks})

def task_create(request):
    if request.method == 'POST':
        form = TaskForm(request.POST)
        if form.is_valid():
            form.save()
            return redirect('task_list')
    else:
        form = TaskForm()
    return render(request, 
        'tasks/task_form.html', 
        {'form': form})

# ~15-20 lines per view

Class-Based View (CBV)

class TaskListView(ListView):
    model = Task
    template_name = 'tasks/task_list.html'
    context_object_name = 'tasks'

class TaskCreateView(CreateView):
    model = Task
    form_class = TaskForm
    template_name = 'tasks/task_form.html'
    success_url = reverse_lazy('task_list')

# ~4-5 lines per view
Result: CBVs mein 60% kam code — zyada readable, zyada maintainable!
Practice Checklist
  • ListView, CreateView, UpdateView, DeleteView imports kiye
  • 4 CBV classes banayi (TaskListView, TaskCreateView, TaskUpdateView, TaskDeleteView)
  • model, template_name, success_url set kiye
  • URLs mein .as_view() use kiya
  • Sab test kiya — list, create, update, delete
